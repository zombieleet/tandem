#+TITLE: claude-pair · Phase 4 · Ecosystem
#+STARTUP: overview

Phase 4 makes claude-pair fit the rest of Emacs and Claude Code. Each
item ships as its own optional file: nothing loads Magit, Embark, Org or
evil unless you use them. Each milestone has automatic tests, a visual
check by you, and its own branch; a commit follows your "Mx passed".

Order: the packages you use first (Magit, Embark with Vertico, Org), then
work across worktrees and machines, then evil keys for others.

** M5 · Remote daemon (postponed 22 Nov 2026, your choice)
- Spike, by design only: no SSH host to test against here (no sshd,
  Docker or remote hosts in your SSH config)
- The way: the daemon runs on the remote host, where the files and
  =claude= are; Emacs starts it there over SSH and talks to it through
  =ssh HOST claude-paird bridge= (a new subcommand copying the socket to
  stdio), with remote paths mapped to TRAMP paths
  (=/home/u/p/x.go= ↔ =/ssh:HOST:/home/u/p/x.go=)
- The cost: one daemon connection per host instead of one (about 17 call
  sites in nine modules), path translation in proposals, opened files,
  Emacs tools, mentions, history, rewind and notes; on the remote, a
  =claude-paird= built for it and Claude Code logged in
- To pick it up: an SSH host to test on (a server you use, or
  =openssh-server= on this machine for =ssh localhost=)
** M6 · ACP adapter (dropped 22 Nov 2026, your choice)
- ACP, the Agent Client Protocol, lets any editor that speaks it use any
  agent that speaks it (Zed, JetBrains, Neovim, Emacs's agent-shell;
  Claude Code, Gemini CLI, Codex). claude-pair has its own protocol for
  Emacs only, with what ACP has no place for (review in buffers, colours,
  Emacs tools, rewind)
- Spike: an official Claude adapter exists (=claude-agent-acp=), and
  claude-pair's features are Emacs Lisp that would not reach other
  editors through ACP, so a =claude-paird acp= would mostly repeat it
